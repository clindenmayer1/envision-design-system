# Using this Storybook

## For engineers

- **Read the API from Controls.** Each component’s **Docs** tab lists every attribute/property and
  event; the **Controls** panel lets you change them live. The attribute names are the real custom-
  element attributes.
- **Consume it two ways.** Every component doc shows both usages:
  ```html
  <!-- any framework / vanilla -->
  <envision-button variant="primary" label="Apply"></envision-button>
  ```
  ```tsx
  // React (thin adapter — no duplicated logic)
  import { Button } from '@envision/react';
  <Button variant="primary" label="Apply" onClick={apply} />
  ```
- **Load tokens once.** `import '@envision/tokens/css'` at the app root. Tokens are CSS custom
  properties and inherit through the shadow boundary, so theming/white-label just works.
- **Run the interactions.** Stories with a `play` function (keyboard, focus, activation) execute in
  the **Interactions** panel; run them all headless with `npm run test:stories` (test-runner).
- **Check accessibility.** The **Accessibility** panel runs axe (WCAG 2.2 AA) on the active story.

## For designers

- **This mirrors Figma.** The components, states, and tokens here are reconciled to the Figma
  library and the shipped product — same values. Use it to confirm real behaviour that a static
  frame can’t show (focus order, keyboard, loading, content overflow, responsive re-composition).
- **Explore states, not just the happy path.** Every component enumerates its meaningful states
  (hover/focus/disabled/loading/error/content-extremes). Use the **Backgrounds** and **Viewport**
  toolbars to check surfaces and breakpoints.
- **Selection & status are never colour-only** — verify the ring + check + label treatments here.

## Conventions in every component

- **Stories** cover the applicable set: default · variants · sizes · hover · focus · active ·
  disabled · loading · validation/error · keyboard · short/long/extreme content · responsive ·
  themes · realistic Envision use cases. No filler permutations.
- **Docs** cover: overview · anatomy · when to use / not use · variants · states · behaviour ·
  accessibility · content considerations · API · token relationships · implementation examples ·
  realistic Envision examples.

## Running locally

```bash
npm run storybook   -w @envision/storybook   # dev server on :6006
npm run build       -w @envision/storybook   # static build (visual-regression source)
npm run test:stories -w @envision/storybook  # run play/a11y tests headless
```

Storybook depends on the built `@envision/components` and `@envision/tokens` — run their builds
first (the monorepo `npm run components` / `npm run tokens`).
